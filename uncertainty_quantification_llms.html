Uncertainty Quantification in LLMs

What is Uncertainty?
What exactly is Uncertainty?
The amount of "I don't know which outcome will happen" that remains even after you've used all the information you have.

It's NOT: confusion, error, or randomness
It IS: residual doubt after reasoning
Can you give me something intuitive?
SituationOur Internal Uncertainty
"The sun will rise tomorrow"Almost zero
"Will it rain tomorrow?"Moderate
"Who will win a coin toss?"High
"What did Bheem eat for lunch on March 12, 45 BC?"Extremely high
How do we (as humans) perceive and measure uncertainty?
1. Probability: "I think there's a 70% chance..." → A spread/distribution over outcomes

2. Confidence/Doubt: "I'm not very confident..." → Instability in your belief

3. Variability across Answers: You ask a kid: "What do you want to be when you grow up?" and it goes like: "Doctor" → "No, Politician" → "Actually AI Engineer (said no one)" → Inconsistency across responses
And the scientific measurement?
ENTROPY: The expected (average) surprise per token in LLMs. Measures how spread-out or unpredictable a probability distribution is.
The Equations

Per Token: H = -Σ p(token) log p(token)

Per Sentence: H = -Σ p(seq) log p(seq)
where p(seq) = ∏ p(tokent | history)

• Sharp distribution (peaked, concentrated) → Low entropy → Very certain
• Spread out distribution (flat) → High entropy → Very uncertain
🎲 Aleatoric Uncertainty: The World's Ambiguity
What is it?

Uncertainty from ambiguity in the input itself. Even a perfect model would be uncertain here because the question has multiple valid answers.

Key Properties:
• Irreducible - can't be fixed even with infinite data
• It's error in the system/task itself, not the model
• If we don't change weights but change sampling (temp, top-k), we're measuring aleatoric

LLM Example

Prompt: "What is my favourite colour?"

Any answer could be correct without more context! This is ambiguous input, not a knowledge gap. Similarly: "Tell me a joke" has thousands of valid answers.

Two Types:
• Homoscedastic: Error rate is constant (sensor gives same 0.1% error always)
• Heteroscedastic: Error rate varies with input (camera: 0.1% in daylight, 5% at night)

Primary Indicators in LLMs:
• High entropy in phrasing choices (many synonyms equally likely)
• Sensitivity to prompt ambiguity
🧠 Epistemic Uncertainty: The Model's Ignorance
What is it?

Uncertainty from the model not knowing something. It's the "I haven't learned this" or "I haven't seen this before" type of doubt.

Key Properties:
• Reducible - can be fixed with more training data, better architecture, or RAG
• Arises from OOD (out-of-distribution) samples or long-tail events
• If we change the model weights (finetuning, SFT), we're working on epistemic issues

LLM Example

Prompt: "What is the capital of Narnia?"

The model was trained on cats vs dogs and you asked about fish. Or you asked about an obscure 15th century poet. The model simply doesn't have the knowledge - this gap can be filled.

Primary Indicators in LLMs:
• Hallucination (confident but wrong answers)
• Inconsistency across rephrasings of same question
• Sycophancy (changing answer when challenged)
The Big Distinction: Where Does Uncertainty Come From?
The spread we're talking about - where exactly does it come from?
It is the Total Uncertainty and where/how it arises gives us two names:

Type Source Nature Remediation LLM Indicators
Aleatoric Data ambiguity, linguistic variety Irreducible Input clarification, constraints High entropy in phrasing; prompt sensitivity
Epistemic Knowledge gaps, model blind spots Reducible RAG, fine-tuning, ensembling Hallucination; inconsistency; sycophancy

The Formula

Total = Aleatoric + Epistemic

Equation 1: Variance Decomposition (Law of Total Variance)

Total Uncertainty =
Varp(θ|D)[E(y|x, θ)] ↑ Epistemic
+
Ep(θ|D)[Var(y|x, θ)] ↑ Aleatoric
In plain English: Total Uncertainty = how much different model versions disagree on the average prediction (Epistemic) + the average spread each model has within its own predictions (Aleatoric).

Equation 2: Information-Theoretic Decomposition

H (Total) =
I(y, θ | x, D) ↑ Epistemic
+
Ep(θ|D)[H(p(y|x, θ))] ↑ Aleatoric
In plain English: Total Entropy = how much knowing the true model parameters would reduce uncertainty about the output (Epistemic) + the average entropy of each model's token distribution (Aleatoric).
When to Use Which Equation?
Variance Decomposition

Best for regression tasks or when you care about continuous outputs (e.g., perplexity scores, confidence scores).

Why? Variance measures squared differences between predictions. When outputs are continuous numbers (like a score from 0 to 1), variance directly captures how "spread out" the predictions are in that number space. It's also easier to interpret: a variance of 0.05 means predictions typically differ by √0.05 ≈ 0.22 from the mean.

Entropy Decomposition

Best for classification/generation tasks with discrete tokens. More common in LLM analysis since we predict discrete tokens.

Why? Entropy measures uncertainty over categorical distributions. LLMs output probability distributions over vocabularies (50K+ discrete tokens), making entropy the natural fit. Entropy is also additive across tokens and measured in bits - directly interpretable as "how many binary questions needed to identify the answer."

⚠️ The Ongoing Debate
What reduces Aleatoric vs Epistemic?

There's high debate in the research community on classification:

Example 1: Adding Context in Prompt
• Changes the input → reduces ambiguity → should be Aleatoric?
• BUT: Fills knowledge gaps in LLM → minimizes Epistemic?
• Different papers use different classifications!

Example 2: Sampling Techniques (temp, top-k, etc.)
• Don't change model weights - raw token probs stay same
• Just filtering/reshaping the distribution
• By definition: not epistemic (no knowledge change)
• But also not removing input ambiguity → not aleatoric either?

Key Insight

Temperature, top-k, etc. just "reshape how much uncertainty you expose" - they don't fundamentally change the source.

🎨 Approach 1: Varying Decoding (Semantic Entropy)
Simple Explanation

Sample N outputs using different temp/top-k/top-p, group by meaning (not words), measure spread over meanings.

How It Works (Pseudocode):
1. Generate N responses using stochastic sampling (high temp)
2. Cluster responses by semantic equivalence using bidirectional NLI
   • If A entails B AND B entails A → same meaning cluster
3. Calculate probability of each meaning cluster
4. Compute entropy over meaning clusters (not tokens!)
5. High semantic entropy → uncertain or hallucinating

📄 Key Paper

"Detecting hallucinations in LLMs using semantic entropy"
Farquhar, Kossen, Kuhn, Gal - Nature 2024

What it Captures:
• Aleatoric: Multiple valid meanings → high entropy
• Epistemic: Inconsistent knowledge → different meanings per sample
🔄 Approach 2: Rephrased Prompts (BayesPE)
Simple Explanation

Ask the same question in N different ways, see if answers stay consistent. Sensitivity to phrasing = instability.

How It Works (Pseudocode):
1. Generate K semantically equivalent prompt rephrasings
2. Query LLM with each rephrased prompt
3. Weight prompts using Bayesian inference over small validation set
4. Aggregate distributions → weighted ensemble prediction
5. High variance across rephrasings → epistemic instability

📄 Key Papers

"Bayesian Prompt Ensembles" - ACL 2024
"SPUQ: Perturbation-Based UQ for LLMs" - EACL 2024

What it Captures:
• Aleatoric (minimize): Clarification resolves ambiguity
• Epistemic (detect): Sensitivity to phrasing reveals unstable knowledge
🤝 Approach 3: N Models (Ensemble)
Simple Explanation

Ask multiple separate models, see if they agree. Disagreement = knowledge gaps.

How It Works (Pseudocode):
1. Query N independent models/checkpoints with same prompt
2. Collect probability distributions from each model
3. Measure disagreement using Jensen-Shannon Divergence (JSD)
4. High JSD → models learned different things
5. Low JSD → consensus = reliable prediction

📄 Key Paper

"MUSE: Multi-LLM Uncertainty via Subset Ensembles" - EMNLP 2024
Uses JSD to identify well-calibrated LLM subsets

What it Captures:
• Epistemic (Gold Standard): Disagreement among independent agents isolates knowledge gaps from data noise
📚 Approach 4: Adding Context (RAG)
Simple Explanation

Give model external info, see if answer becomes more consistent. Reduced uncertainty = filled knowledge gap.

How It Works (Pseudocode):
1. Query model WITHOUT context → baseline response & confidence
2. Retrieve relevant context from knowledge base
3. Query model WITH context → new response & confidence
4. Compare uncertainty before vs after
5. Reduced uncertainty = was a knowledge gap (now filled)
6. Residual uncertainty = inherent ambiguity (aleatoric)

📄 Key Papers

"Uncertainty as Feature Gaps" - Bakman et al. 2025
"UncertaintyRAG" - Li et al. 2024

What it Captures:
• Epistemic (minimize): Context fills parametric knowledge gaps
• Residual after RAG = Aleatoric (inherent to task)
📊 Approach 5: Token Probabilities / P(True)
Simple Explanation

Look at raw logits - how confident is model about each token? Low probability tokens = uncertain predictions.

How It Works (Pseudocode):
1. For each generated token, check its probability
2. Aggregate metrics:
   • Perplexity: exp(avg negative log-likelihood)
   • Min-Prob: Lowest token probability in sequence
   • P(True): Ask model "Is this answer true?" → check prob of "True"
3. High perplexity / low min-prob → uncertain prediction

📄 Key Paper

"Language Models (Mostly) Know What They Know"
Kadavath et al. 2022 - Anthropic research on P(True)

What it Captures:
• Aleatoric: Per-token distribution reflects phrasing ambiguity
• P(True) attempts Epistemic detection (self-assessment)
💬 Approach 6: Verbalized Confidence
Simple Explanation

Just ask the model "How confident are you?" - let it state a number (0-100%).

How It Works (Pseudocode):
1. Prompt: "Answer this question and rate your confidence (0-100%)"
2. Optionally: Use Chain-of-Thought first (improves calibration)
3. Extract stated confidence score from response
4. Compare stated confidence vs actual accuracy
5. Calibration error = mismatch between stated and actual

📄 Key Papers

"Can LLMs Express Their Uncertainty?" - ICLR 2024
"Overconfidence is Key" - Groot & Valdenegro-Toro 2024

What it Captures:
• Attempts Epistemic (self-assessment of knowledge)
• ⚠️ Known Issue: LLMs are overconfident! Cluster around 80-100% regardless of accuracy ("human mimicry")
🎭 Approach 7: Sycophancy Test
Simple Explanation

Bias model toward wrong answer, see if it changes its mind. If it flips easily → no real knowledge.

How It Works (Pseudocode):
1. Get initial answer from model
2. Present opposing "hint" or suggestion
   • "Actually, I think the answer is X. Are you sure?"
3. Ask model to reconsider
4. If model flips to wrong answer → sycophantic (low conviction)
5. If model holds firm → high epistemic confidence

📄 Key Paper

"Accounting for Sycophancy in LLM Uncertainty Estimation"
Sicilia et al. 2024 - Proposes SyRoUP (Sycophancy-Robust UQ)

What it Captures:
• Epistemic (detect): High susceptibility = lack of true knowledge conviction
🎲 Approach 8: Monte Carlo Dropout (Advanced)
Simple Explanation

Randomly "turn off" parts of model multiple times, see if answers vary. Each dropout mask = different "thinned" network.

How It Works (Pseudocode):
1. Keep dropout ACTIVE during inference (normally off)
2. Run same input T times with different dropout masks
3. Each forward pass = different effective θ
4. Collect T different outputs
5. Variance across T passes ≈ epistemic uncertainty

📄 Key Paper

"Dropout as Bayesian Approximation: Representing Model Uncertainty in Deep Learning"
Gal & Ghahramani 2016 - Foundational paper linking dropout to Bayesian inference

What it Captures:
• Epistemic: Parameter uncertainty via pseudo-ensemble
• ⚠️ Practical Note: Less practical for very large LLMs (compute cost, architecture changes)
